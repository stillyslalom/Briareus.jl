VisRad interchange

Readers and writers for the files VisRad (Prism Computational Sciences, VISRAD 21.1.1) imports and exports — NIF SST pointing, the Laser Beam Summary table, time-dependent beam powers, element and power-summary tables, workspaces (.vrw: target components with bundled CAD, and beams) — and a benchmark kit that writes everything needed to rebuild a Briareus case in VisRad together with Briareus's results for comparison. Formats follow the VisRad manual; the provenance and confidence of each detail are in reference/research-notes.md ("VisRad interchange formats").

Briareus.VISRAD_PHASE_PLATES — Constant
VISRAD_PHASE_PLATES

VisRad's built-in phase-plate profiles (VR/power_sources/phase_plate_params.html), keyed by the manual's names: (facility, major, minor, order, level) with radii in µm (the manual's "(mm)" header is a µ rendered in the Symbol font) measured where the intensity is level × peak — exp(-1) (1/e) for the OMEGA, OMEGA EP and GEKKO tables, 0.5 (HWHM) for NIF CPPs, 0.03 for LMJ. Circular plates have minor == major. order is the super-Gaussian exponent n of exp(-[(x/a)²+(y/b)²]^(n/2)) (VR/power_sources/set_laser_profile_props.html). The NIF n = 2.0 entries are the manual's placeholder where no data were available. The GEKKO table does not state its radius definition; 1/e is an assumption. See visrad_spot.

Briareus.VISRAD_SST_COLUMNS — Constant
VISRAD_SST_COLUMNS

Column headers of the NIF SST beam-pointing CSV, as VisRad maps them when importing an SST file (screenshot in VR/intro/revision_history.html, v21.0.0, and VR/power_sources/import_laser_beam_data_csv.html): beam name, aim point x, y, z (mm, target-chamber Cartesian about TCC) and defocus (mm).

Briareus.compare_visrad — Method
compare_visrad(kit_dir; elements = nothing, power_summary = nothing, observe = :capsule,
               names = Dict(), terms = (0, 2, 4), lmax = 4, io = nothing)
    -> Vector{NamedTuple}

Compare a kit written by write_visrad_kit with VisRad's results for the same case.

  • elements: VisRad's Surface Element Properties export for the observed component (read_visrad_table). The polar and azimuthal columns (headers containing "polar"/"theta" and "azim"/"phi", degrees, in the component's own frame — for an unrotated sphere the chamber frame) and "Flux In" (TW/cm²; a TW/mm² header is converted) are fitted exactly as Briareus's elements were (visrad_legendre_fit over terms, visrad_ylm_fit to lmax).
  • power_summary: VisRad's Power Summary, as a file (read_visrad_table; object names are row labels) or a Dict(object => Dict(column => value)) typed from the dialog, columns as in VisRad ("Laser Pwr Dep", "Incident Rad Pwr", "Emitted Rad Pwr", "Pwr Src Term", "Surface Area"; TW and cm²). names maps VisRad object names to Briareus component names, e.g. Dict("hohlraum_barrel" => "wall").

Returns rows (; quantity, unit, briareus, visrad, difference, relative) and prints them to io when given.

Briareus.read_visrad_powers — Method
read_visrad_powers(path; template = nothing) -> Dict{Symbol,PulseShape}

Read a VisRad time-dependent beam-power CSV: first column time (ns; a "(s)"/"(sec)" or "(ps)" unit in its header is converted), then one power column (TW) per beam headed by the beam name (VR/files/laser_beam_data_files.html). Negative powers are set to zero as VisRad does on import (VR/power_sources/import_tdep_beam_powers.html).

Without a template the keys are the normalized beam names as Symbols (BL115 → :B115, :Beam_10). With a template beam set the keys are the template's names: beams match by name, and a NIF quad gets the sum of its four beams' pulses (on the union of their knots); template beams absent from the file have no key. Beams at time t are with_pulses(beams, P, t; by = :beam) (with_pulses).

Briareus.read_visrad_pulse_shape — Method
read_visrad_pulse_shape(path) -> PulseShape

Read one of VisRad's standard laser pulse-shape files (data/laser_pulse_shapes of the installation): a two-column ASCII table of power (W) versus time (s) (VR/files/laser_pulse_shape_files.html), returned in ns and TW. The column order is not stated; time first is an assumption, and a first column that is not sorted while the second is triggers the swap. Non-numeric lines are skipped.

Briareus.read_visrad_sst — Method
read_visrad_sst(path; template = nif_beams(), absent = :off, units = nothing)
    -> Vector{Beam}

Read a NIF SST pointing CSV (written by VisRad's File | Export Laser Beam Data | NIF SST Beam Data, by the SST, or by write_visrad_sst) and apply it to template: each beam found gets the file's aim (mm, chamber Cartesian about TCC, defocus not applied) and defocus (mm); power and spot are kept. Following VisRad's import (VR/power_sources/import_laser_beam_data_csv.html), template beams absent from the file are turned off (absent = :off, power 0); :keep leaves them unchanged and :error throws.

Beam names match case-insensitively, with BL115 read as B115. With a quad template (nif_quads()), each quad takes the mean aim and defocus of its four beams, with a warning if they differ by more than 1 µm. The header row is found by its "Beam Aim Point" columns; lines before it are skipped, extra columns ignored. Units come from the headers ("(mm)", "(cm)", "(um)"); units (mm per file unit) overrides them.

Briareus.read_visrad_summary — Method
read_visrad_summary(path; template = nothing, absent = :off, spot_definition = :auto,
                    rotation_sense = :beam, angle_tol = 0.05) -> Vector{Beam}

Read a VisRad Laser Beam Summary CSV (Export Data in the Laser Beams Summary dialog, VR/power_sources/laser_summary_table.html; also written by write_visrad_summary). Columns are recognized by header, so older layouts and extra columns are accepted.

Conversions:

  • Pointing. "TC Pt Pos-x/y/z" (cm) is the beam's focus in the target-chamber frame: the Reference Point plus the focus offset along the beam. This follows from the manual's own example table (VR/power_sources/images/laser_summary.jpg): beams pointed at the same foil-frame Reference Point with focus offset -0.215 cm have TC positions that differ by exactly 0.215 cm × the difference of their port vectors. So aim = 10·TC + defocus·port (mm) with defocus = 10·focus offset (cm → mm). When the TC columns are absent, the Reference Point is taken from "Pt Param-1/2/3" (cm; Cartesian, cylindrical (r, z, φ) or spherical (r, θ, φ), degrees), which works only for references in the target-chamber frame ("Target Chamber" or "TCC"). When both are present they are cross-checked.
  • Power. "Power" (TW; for NIF the sum of the 3ω, 2ω and 1ω cones, VR/power_sources/nif_beam_params.html). Time-dependent beams show their peak as "T-<peak>", read as the peak with a warning. Off beams get power 0.
  • Spot. "R0" major/minor are radii (µm) at the spot-size definition level, "36.8% (1/e)", "50%" or "5%" of peak (VR/power_sources/set_laser_profile_props.html); they become 1/e semi-axes a (major), b (minor) of the same super-Gaussian exp(-[(x/a)²+(y/b)²]^(n/2)), which is VisRad's focal profile. The definition comes from an "R0 Def" column if present, else spot_definition: :auto uses the level of a recognized built-in phase plate (VISRAD_PHASE_PLATES; NIF CPP radii are HWHM) and 1/e otherwise (VisRad's default for Custom Supergaussian, assumption for other models); :e, :hwhm, :pct5 or a number force it. The exponent n comes from an "SG Exponent" column, else the phase-plate table, else the template beam. A "Uniform" profile (flat across R0 at focus) is approximated by n = 50 with 1/e radius R0.
  • Rotation. "Rot Angle" is the minor-axis rotation ρ (degrees, clockwise from vertical; ρ = 0 puts the major axis "nearly horizontal"). Briareus's angle of the major axis from θ̂ toward φ̂ is 90° − ρ for rotation_sense = :beam (spot seen looking along the beam) and 90° + ρ for :target (seen from TCC). The manual does not say which; :beam is an assumption to verify. Horizontal is φ̂ of the beam's NIF quad port (quad of the template beam), which is turned 1.6–5.3° from the beam's own φ̂: measured in VisRad 21 to 0.02° on 48 beams. Beams of no NIF quad use their own φ̂.
  • DPR, halo, f-number and wavelength are not in the file: DPR "On" is warned about and ignored (VisRad splits such OMEGA beams into two cones 85 µm apart); the rest come from the template.

With a template, beams are matched by name (case-insensitive; "BL115" reads as "B115", "10" and "BL-10" as "Beam_10"), port angles are checked against the file's "Polar Ang"/"Azm Ang" (warning beyond angle_tol degrees — a frame or naming mismatch), template beams absent from the file follow absent (:off, :keep, :error; VisRad omits hidden unused beams), and NIF quads aggregate their four beams (mean aim and defocus, summed power). Without a template, beams are built from the file's port angles.

Briareus.read_visrad_table — Method
read_visrad_table(path; header = nothing) -> (; header, labels, data)

Read a multi-column ASCII table exported by VisRad — the Surface Element Properties table (File | Save Data for Object / All Objects / Selected Rows, and the *.sed files of a run; VR/results/display_surf_elem_table.html, VR/simulation_times/config_sim_params.html) or a Power Summary (*.psd). The manual shows the columns (e.g. "Z (cm)", "Azim. ang (deg)", "Radius (cm)", "Surf Index", "Emis T (eV)", "Rad T (eV)", "Flux In (TW/cm2)", "Flux Out (TW/cm2)", …; VR/results/images/surf_elem_table.jpg) but not the file layout, so the reader is tolerant (assumption throughout): comma-, tab- or whitespace-separated; data rows are the most common shape of lines ending in numbers, with any leading non-numeric text kept as the row's label (an object name); the header is the last non-data line before the first data row, split on the delimiter, on runs of 2+ spaces, or by attaching "(unit)" tokens to the words before them. Pass header (a vector of names for the numeric columns) when that fails.

Returns the numeric column names, row labels (empty strings when none) and an nrows × ncols matrix.

Briareus.visrad_legendre_fit — Method
visrad_legendre_fit(theta, values; terms = 0:4, weights = nothing) -> Vector

Least-squares fit f(θ) = Σₗ Aₗ Pₗ(cos θ) over the given terms, as in VisRad's Surface Element Statistics (coefficients up to A4, each term selected by a check box; VR/results/display_surf_elem_table.html). theta in degrees; returns A indexed l+1 (zero for unused terms), so A[3]/A[1] is P2/P0. Unweighted by default — VisRad's weighting is not documented (assumption); pass element areas as weights to weight. Apply the same fit to Briareus and VisRad element values for a like-for-like comparison.

Briareus.visrad_spot — Method
visrad_spot(plate; rotation = 0.0, rotation_sense = :beam) -> SuperGaussianSpot

Briareus spot equivalent to a VisRad built-in phase plate (VISRAD_PHASE_PLATES name, or a CMT/summary-table spelling such as "Rev3 Inner Cone 2W CPP" or "OMEGA E-IDI-300 DPP"). The tabulated radii, defined at the table's intensity level, are converted to 1/e semi-axes (mm) of the same super-Gaussian: r_1/e = r_f / (ln(1/f))^(1/n). rotation is VisRad's minor-axis rotation (degrees, clockwise from vertical, 0 = major axis horizontal); see read_visrad_summary for rotation_sense.

Briareus.visrad_ylm_fit — Method
visrad_ylm_fit(theta, phi, values; lmax = 4, weights = nothing) -> Vector

Least-squares fit to VisRad's real spherical harmonics (VR/results/display_surf_elem_table.html): Y_LM = N_LM P_L^M(cos θ) for M = 0 and √2 N_LM P_L^|M|(cos θ) × cos Mφ (M > 0) or sin |M|φ (M < 0), with N_LM = √((2L+1)(L−M)!/(L+M)!), so Y_00 = 1 and A_00 is the mean (the manual's example: mean 9.736, A_00 = 9.739) and A_L0 = A_L/√(2L+1) for the Legendre A_L (its example: 1.143·√5 = 2.556 vs A_2 = 2.563). Angles in degrees; coefficients in Briareus's flat mode_index order. These are Briareus's orthonormal ylm_moments times √(4π). Whether VisRad's P_L^M carries the Condon–Shortley phase is not stated; none is assumed (signs of odd-M coefficients may flip); √(Σ_M A_LM²)/A_00 is unaffected.

Briareus.write_visrad_kit — Method
write_visrad_kit(dir, target, beams; model = nothing, op = nothing, pulses = nothing, by = :group,
                 time = 0.0, observe = :capsule, terms = (0, 2, 4), lmax = 4,
                 rotation_sense = :beam, notes = "") -> NamedTuple

Write everything needed to rebuild a Briareus case in VisRad, together with Briareus's results for comparison (compare_visrad), into directory dir:

  • pointing_sst.csv — per-beam pointing in the NIF SST format (write_visrad_sst); import with File | Import Laser Beam Data | Pointing Data, Custom CSV, units mm.
  • beam_summary.csv — the full beam set in Laser Beam Summary layout (write_visrad_summary): port angles, pointing, focus, power, 1/e spot radii, exponents and rotations.
  • powers.csv — per-beam time-dependent powers (write_visrad_powers), when pulses is given (keyed by, as in write_visrad_powers); beam powers are then evaluated at time.
  • briareus_beams.csv — the canonical Briareus beam table (write_beam_table).
  • README.txt — target geometry (component shapes and dimensions in mm, cm and µm, materials, albedos and conversion efficiencies), beam settings, and the VisRad steps.
  • briareus_results.csv — quantity,value,unit rows: per-component "Laser Pwr Dep", "Pwr Src Term" (conversion × laser), "Incident Rad Pwr" (Σ H·A), "Emitted Rad Pwr" (Σ B·A), all TW, and "Surface Area" (cm²), named as VisRad's Power Summary columns; the laser power that misses or strikes outer surfaces; and for observe the mean incident flux (TW/cm²), the VisRad-style Legendre fit (visrad_legendre_fit over terms) and per-L amplitudes of the VisRad spherical-harmonic fit (visrad_ylm_fit).
  • briareus_<observe>_elements.csv — per-element polar/azimuthal angle about the component's center (degrees), area (cm²), incident flux and absorbed laser flux (TW/cm²).

The deposition uses op (default DepositionOperator(target, beams)) and the radiation model (default RadiationModel(target)). Returns (; dir, files, results) with results a Dict of the quantities in briareus_results.csv.

Briareus.write_visrad_powers — Method
write_visrad_powers(path, beams, pulses; by = :group, times = nothing) -> path
write_visrad_powers(path, pulses::AbstractDict{Symbol,PulseShape}; times = nothing) -> path

Write a VisRad time-dependent beam-power CSV (VR/files/laser_beam_data_files.html): header time (ns) then one column per beam named as VisRad names beams (B115 for NIF, Beam_10 for OMEGA), rows of time (ns) and power (TW per beam). Import it with File | Import Laser Beam Data | Time-Dependent Powers (VR/power_sources/import_tdep_beam_powers.html); for NIF VisRad assigns the powers to the 3ω (blue) cones.

pulses takes the forms of with_pulses: a PulseShape for every beam, or a Dict/NamedTuple keyed by group (default), quad, beam name (by = :beam, as read_visrad_powers returns them) or a function of the beam. The second form writes a Dict keyed by beam name as it is. NIF quads expand to their four beams at a quarter of the quad's power each. Times default to the union of all pulse knots, so piecewise-linear pulses are reproduced exactly when each starts and ends at zero power (a PulseShape is zero outside its table; a pulse that starts or ends at a finite power gets a ramp to its neighbors' knots instead). Briareus beam names that are not facility names (e.g. omega_beams()'s hohlraum-frame B01…) are written as they are; rename them first.

Briareus.write_visrad_sst — Method
write_visrad_sst(path, beams; include_off = false) -> path

Write beam pointing as a NIF SST CSV (VISRAD_SST_COLUMNS): one row per NIF beam ("B111"–"B468"), aim point in target-chamber Cartesian coordinates about TCC (mm) without the defocus applied, and the defocus (mm, positive moves the focus along the propagation direction). This is VisRad's export format (VR/files/laser_beam_data_files.html, "NIF SST Data Files") and imports into VisRad through File | Import Laser Beam Data | Pointing Data, "Custom" CSV, which recognizes these headers (VR/power_sources/import_laser_beam_data_csv.html).

NIF quads (names "Q11T"…, e.g. nif_quads()) are written as their four beams with the quad's pointing. VisRad turns on exactly the beams that have pointing data, so beams with zero power are left out unless include_off.

The file carries no powers or spots: pair it with write_visrad_powers and set the spot model in VisRad (see write_visrad_kit).

Briareus.write_visrad_summary — Method
write_visrad_summary(path, beams; rotation_sense = :beam, cluster = b -> string(b.group),
                     profile = "Custom Supergaussian", extras = true) -> path

Write beams in the layout of VisRad's Laser Beam Summary CSV, one row per VisRad beam (NIF quads expand to their four beams with a quarter of the power each): cluster, beam ID, on/off (power > 0), port polar/azimuth (degrees), pointing reference "Target Chamber"/"Cartesian" with the aim as Pt Param-1/2/3 (cm), focus offset (cm), focus position "TC Pt Pos" (cm, aim + defocus·k), power (TW), DPR "Off", spatial profile model, R0 major/minor as 1/e radii (µm), and the minor-axis rotation (degrees; see read_visrad_summary for rotation_sense). extras appends "SG Exponent" and "R0 Def" ("36.8% (1/e)") so that the file is self-contained.

Columns through "TC Pt Pos-z" reproduce the v21 dialog's headers; the names of the later columns are not shown in the manual (assumption), and halo parameters are not written (VisRad has none). Use this file for records and for read_visrad_summary; to set pointing in VisRad, import write_visrad_sst, whose format is documented.

Briareus.VisRadObject — Type
VisRadObject

One target component of a VisRad workspace, as read by read_visrad_workspace.

Fields: name; VisRad's object type code and the kind Briareus recognizes (:mesh for CAD/generalized meshes, :sphere, :rectangle, :cylindrical_hohlraum, :other); the folder path in VisRad's component tree ("" at the top); params, every key = value line of the object verbatim; rotation and position (mm), the object's frame in the target-chamber frame (x_chamber = rotation * x_object + position); mesh, the surface in the chamber frame (mm) for meshes (one patch per VisRad surface element) and nothing otherwise; albedo, conversion (x-ray conversion efficiency) and reflectivity (laser); the flags radiosity, laser (direct laser deposition) and visible; and color (RGB in [0, 1]).

Briareus.read_visrad_workspace — Method
read_visrad_workspace(path; template = nothing, absent = :off, spot_definition = :auto,
                      rotation_sense = :beam, angle_tol = 0.05) -> VisRadWorkspace

Read a VisRad workspace (.vrw, the text format of VisRad 20–21, "Workspace Format ID = 11"): its target components, including CAD imported as generalized meshes, and its laser beams. Lengths are converted from cm to mm; every object and beam frame is resolved to the target-chamber frame. Build a Briareus target from the components with visrad_target.

Components become VisRadObjects. CAD meshes keep VisRad's surface elements as patches (one per triangle). Spheres, rectangles and cylindrical hohlraums are meshed on VisRad's grid when converted by visrad_target. Objects are placed by VisRad's orientation angles and position (VR/grid/specifying_orient_angles.html), relative to the chamber or to another component.

Beams. Port angles and f-number come from the file. Pointing at TCC or at a point given in the chamber's or a component's frame is supported; the point is the aim and the focus offset (cm) the defocus (mm), as in read_visrad_summary. Power is the 3ω (blue cone) power in TW for beams with 3ω on, and 0 otherwise: the power column times the beam's power multiplier when enabled and, under VisRad's "Fraction of Total Beam Power" red/green model (where that column is the total), times $1 - f_G - f_R$. Spots are VisRad's super-Gaussian radii (µm), exponent and minor-axis rotation, converted as in read_visrad_summary: radii that match a built-in phase plate (VISRAD_PHASE_PLATES) are read at that plate's level (HWHM for NIF CPPs), others at spot_definition (:auto = 1/e), and a NIF beam's rotation is relative to its quad's horizontal (the quad from the template or, without one, from the beam's name). Unconverted light, time-dependent powers, energy normalization and DPR are warned about and not imported.

With a template (e.g. nif_beams()), the file's pointing, power and spots are applied to the template's beams by name and its other properties (halo, wavelength, quad, group) are kept; port angles are checked to angle_tol degrees and absent handles template beams missing from the file, as in read_visrad_summary. Without one, beams are built from the file, grouped by VisRad cluster.

Briareus.visrad_component — Method
visrad_component(object; material = nothing, two_sided = false, orient = false,
                 toward = (0, 0, 0), coarsen = nothing, remesh = nothing,
                 fit = remesh !== nothing, primitive_h = nothing) -> Vector{Component}

Briareus components for one VisRadObject, in the chamber frame (mm). The material defaults to the object's albedo and x-ray conversion efficiency. CAD meshes give one component radiating from the front of VisRad's surface elements (counterclockwise winding, assumption), or from both sides when two_sided. VisRad does not let users edit the normals of imported CAD (VR/grid/import_export_cad_files.html), and tessellated CAD often faces the wrong way: in the NIF workspace this reader was built from, the inner hohlraum wall faces away from the cavity. orient = true repairs the winding with orient_mesh: consistent across shared edges, closed solids facing out of their material, open sheets facing the point toward (mm, chamber frame; by default the target chamber center). two_sided = true instead radiates from both sides (thin shells are then modeled as two radiating sides). CAD needs fewer, compact elements before view factors: remesh (mm) divides the surface into near-planar elements of about that size whatever the facets' shapes (remesh_mesh; long slivers are cut), while coarsen (mm) only merges whole near-coplanar facets up to that size (coarsen_mesh; slivers longer than the size stay). fit (on by default with remesh; or a named tuple of curved_components and fit_surfaces keywords) then splits a remeshed CAD part into its cylinders, cones and spheres, each with its exact surface fitted to the CAD facets, and the rest (curved_components; curved faces of under 10⁻³ of the part's area stay flat unless minfraction = 0), so the radiation model integrates on the curved walls as it does for a primitive hohlraum. The pieces, <name>/cyl1, …, <name>/rest, keep the object's name as their part, which the name-taking functions and reports use (see cad_target); fit = false keeps one flat component. Rectangles give one component (normal +z before orientation), spheres one with a SphereSurface, and cylindrical hohlraums five — <name>_wall, _cap_top, _cap_bottom and the apertures _leh_top, _leh_bottom — with the curved surfaces hohlraum uses, all on VisRad's grid (Number of mesh pts, which reproduces VisRad's element table), or with primitive_h (mm) on Briareus's grid for elements of about that size (hohlraum_counts, capsule_counts), e.g. to resolve a spot on a foil that VisRad meshes coarsely. Other object types return no components (with a warning).

Briareus.visrad_deposition — Function
visrad_deposition(workspace, target = visrad_target(workspace);
                  sources = visrad_power_sources(workspace)) -> Vector{Float64}

VisRad's absorbed laser power per element of target (TW), from the direct laser power source of a computed workspace (visrad_power_sources): each VisRad surface element's value (TW/cm²) times its area. This is the convention of deposit(...).element, so VisRad's and Briareus's depositions on the same target compare element by element and per component (sum(P[elements(target, :wall)])).

target must hold the workspace's objects as visrad_target(workspace) or visrad_component build them, one component per object (named after it) on VisRad's own elements. Each component is checked against the object's elements; a component remeshed, coarsened, fitted or cut to a cavity is refused, so the target compared with VisRad is not the one a radiation study remeshes (see visrad_target): build both from the workspace, and compare depositions on this one. Elements are matched by:

  • CAD meshes (generalized meshes): one Briareus patch per VisRad surface element, in the file's connectivity order. The order is VisRad's own; it is confirmed by Briareus's deposition matching VisRad's element by element (correlation 1.0000, 0.9% rms with VisRadProfile) on 2388 wall elements of a NIF workspace.
  • Rectangles on VisRad's grid: VisRad's elements run the local x fastest (measured on a foil workspace).
  • Spheres and cylindrical hohlraums: VisRad's element order is not established (only the counts are). An object of these kinds with any laser power is refused; leave it out of the target (visrad_target(ws; select)) to map the rest.

A two-sided component takes the power on its front elements (VisRad's table has one value per surface element). Objects with laser power but no component in target are warned about; components without a VisRad table stay zero.

Briareus.visrad_power_sources — Method
visrad_power_sources(workspace; stale = :error) -> (; time, units, tables)

VisRad's power-source results saved in a computed workspace (a .vrw path or a VisRadWorkspace, re-read from its path): the [Power Source Data] section, which VisRad writes after computing the power sources. Per object it lists one row per surface element: index (0-based), direct laser power source (TW/cm², the laser power absorbed per area averaged over the element), uniform source, albedo, x-ray conversion efficiency, laser reflectivity, pre-reflection laser power, numbers of red and blue cones hitting the element, and minimum overlap angles at 1ω and 3ω.

tables maps each object's name to a NamedTuple of column vectors, named from the section's own header (:surface_index, :direct_laser_pwr_source, :uniform_source, :albedo, :x_ray_conv_efficiency, :laser_reflectivity, :pre_reflect_laser_pwr, :n_red_cones_hitting_surf, :n_blue_cones_hitting_surf, :min_angle_overlap_1w, :min_angle_overlap_3w in VisRad 20–21); integer columns are Int. units maps column names to the header's units ("TW/cm2", "deg", ""), and time is the simulation time (ns) the sources were computed for.

A workspace saved before computing, or changed since, shows "Power sources are not up to date" and holds no tables: that is an error, or nothing with stale = :nothing. Tables of the same layout in other sections (beam capture and clearance data) are not read. Map the direct laser source onto a Briareus target with visrad_deposition.

Briareus.visrad_target — Method
visrad_target(workspace; select = o -> o.radiosity || o.laser, materials = Dict(),
              two_sided = false, orient = false, toward = (0, 0, 0),
              coarsen = nothing, remesh = nothing, fit = remesh !== nothing,
              inside = nothing, visibility = :sampled, closed = false) -> Target

Target built from the components of a VisRad workspace (read_visrad_workspace) for which select(object) is true — by default those that VisRad includes in its radiosity or direct-laser calculation. materials maps object names (Strings or Symbols) to a Material overriding the file's albedo and conversion efficiency; a name that is not an object of the workspace is an error. two_sided (a Bool, or a function of the object) makes surfaces radiate from both sides; see visrad_component for why CAD meshes often need it, and for orient, toward, remesh, coarsen and fit (which apply to CAD meshes: repaired windings, elements of about remesh or coarsen mm, and exact cylinders, cones and spheres for the radiation model).

CAD meshes can hold hundreds of thousands of triangles, and each becomes a radiating element. That is fine for ray tracing (deposition, clearance, imaging) but too many for view factors; select the parts that matter for the radiation problem, e.g. select = o -> o.folder == "Hohlraum" or by name, and remesh them. inside, a point (mm, chamber frame) in the cavity, keeps only the elements that bound the free space around it (enclosure with its defaults; call it on the full target for the options and a per-component account of what was dropped). It needs consistent windings (orient = true). The selection runs on the CAD facets as oriented, remesh or coarsen then divide only the facets kept (much cheaper when most of the assembly lies outside the cavity), and a second selection on the resulting elements drops those that average too little flux. fit then applies to the elements kept, fitted on the kept facets. The CAD meshes go through these steps in cad_target, which takes the other components as they are (into the selection, but not remeshed or fitted); it does the same for CAD read from STL files. visibility is the target's default view_factors visibility rule (:sampled, as for cad_target: workspaces carry entrance-hole washers and CAD with rims), and closed = true declares the target a closed enclosure (balanced view factors), as for cad_target: only when apertures close every opening (see open_fraction).

A comparison with VisRad and a radiation study usually take two targets from the same workspace. visrad_deposition maps VisRad's per-element deposition only onto components on VisRad's own elements, so it takes a target built without remesh, coarsen, fit and inside (e.g. visrad_target(ws), with the same select), on which a DepositionOperator reproduces VisRad's calculation element by element; the view factors take the remeshed, cut target. The beams serve both, with one DepositionOperator per target.

Briareus.write_visrad_workspace — Method
write_visrad_workspace(path, template, beams; angle_tol = 0.05) -> path

A VisRad workspace with the pointing, focus, power and on/off of beams written into a copy of the workspace template (a .vrw file, e.g. the one a design was imported from with read_visrad_workspace). Each beam row of the template whose name matches a beam gets that beam's aim, as a Cartesian position in the row's own reference frame (cm), its focus offset defocus (cm), its power as the 3ω power column (divided by the row's power multipliers and, under the "Fraction of Total Beam Power" red/green model, by its blue fraction, so VisRad's blue cone carries the beam's power) and on (power > 0) or off. Everything else is copied byte for byte: the target components and their frames, the spots, pulse shapes and VisRad's settings stay VisRad's own. Numbers are written in place at the template's column widths and decimals (0.1 µm for positions).

A computed template's results (power sources, radiosities, beam capture and clearance) are reset to "not up to date" when any row is written: they belong to the old beams.

Rows without a matching beam are left as they were, and beams without a row are reported in a warning: the template sets which beams exist. A beam whose port differs from its row's by more than angle_tol degrees is refused (ports cannot be changed). Time-dependent power tables and energy normalization in the template are left as they are, so a row that uses them does not take the constant power (warned).
