VisRad interchange

This page documents readers and writers for the files VisRad (Prism Computational Sciences, VISRAD 21.1.1) imports and exports: NIF SST pointing, the Laser Beam Summary table, time-dependent beam powers, element and power-summary tables, and workspaces (.vrw, with target components, bundled CAD and beams). It also documents a benchmark kit that writes everything needed to rebuild a Briareus case in VisRad, together with Briareus's results for comparison. Formats follow the VisRad manual; the sources and confidence of each detail are in reference/research-notes.md ("VisRad interchange formats").

Briareus.VISRAD_NIF_PLATES — Constant
VISRAD_NIF_PLATES

The VisRad phase plate (a VISRAD_PHASE_PLATES name) for each NIF cone: Rev3 Inner on the 23.5° cone, 1.0 Rev1a Inner on the 30° cone, Rev3 Outer on the 44.5° cone and Rev1 Outer on the 50° cone. The assignment is that of the measured CPP profiles behind nif_spot (LMF phase-plate table, 2020-10-15). VisRad lists the four plates among its NIF CPPs (VR/power_sources/import_nif_cmt_data_file.html) and tabulates their radii and exponents (VR/power_sources/phase_plate_params.html). Other campaigns field other plates. This is a default for VisRad parity and is not a facility record.

Briareus.VISRAD_PHASE_PLATES — Constant
VISRAD_PHASE_PLATES

The built-in phase-plate profiles of VisRad (VR/power_sources/phase_plate_params.html), keyed by the names in the manual, as (facility, major, minor, order, level). The radii are in µm; the "(mm)" header in the manual is a µ rendered in the Symbol font. They are measured where the intensity is level × peak: exp(-1) (1/e) for the OMEGA, OMEGA EP and GEKKO tables, 0.5 (HWHM) for NIF CPPs and 0.03 for LMJ. Circular plates have minor == major. order is the super-Gaussian exponent n of exp(-[(x/a)²+(y/b)²]^(n/2)) (VR/power_sources/set_laser_profile_props.html). The NIF entries with n = 2.0 are placeholders in the manual where no data were available. The GEKKO table does not state its radius definition, and 1/e is an assumption. See visrad_spot.

Briareus.VISRAD_SST_COLUMNS — Constant
VISRAD_SST_COLUMNS

Column headers of the NIF SST beam-pointing CSV, as VisRad maps them when it imports an SST file (screenshot in VR/intro/revision_history.html, v21.0.0, and VR/power_sources/import_laser_beam_data_csv.html). The columns are the beam name, the aim point x, y, z (mm, target-chamber Cartesian about TCC) and the defocus (mm).

Briareus.compare_visrad — Method
compare_visrad(kit_dir; elements = nothing, power_summary = nothing, observe = :capsule,
               names = Dict(), terms = (0, 2, 4), lmax = 4, io = nothing)
    -> Vector{NamedTuple}

Compare a kit written by write_visrad_kit with the VisRad results for the same case.

  • elements: the VisRad Surface Element Properties export for the observed component (read_visrad_table). The polar and azimuthal columns are those whose headers contain "polar"/"theta" and "azim"/"phi", in degrees and in the component frame, which for an unrotated sphere is the chamber frame. They and "Flux In" (TW/cm²; a TW/mm² header is converted) are fitted exactly as the Briareus elements were (visrad_legendre_fit over terms, visrad_ylm_fit to lmax).
  • power_summary: the VisRad Power Summary, as a file (read_visrad_table, with object names as row labels) or a Dict(object => Dict(column => value)) typed from the dialog. The columns are as in VisRad ("Laser Pwr Dep", "Incident Rad Pwr", "Emitted Rad Pwr", "Pwr Src Term", "Surface Area"; TW and cm²). names maps VisRad object names to Briareus component names, e.g. Dict("hohlraum_barrel" => "wall").

Returns rows (; quantity, unit, briareus, visrad, difference, relative) and prints them to io when given.

Briareus.read_visrad_powers — Method
read_visrad_powers(path; template = nothing) -> Dict{Symbol,PulseShape}

Read a VisRad time-dependent beam-power CSV. The first column is time in ns, and a "(s)"/"(sec)" or "(ps)" unit in its header is converted. One power column (TW) per beam follows, headed by the beam name (VR/files/laser_beam_data_files.html). Negative powers are set to zero, as VisRad does on import (VR/power_sources/import_tdep_beam_powers.html).

Without a template the keys are the normalized beam names as Symbols, so that BL115 becomes :B115, and OMEGA beams become keys such as :Beam_10. With a template beam set the keys are the names of the template. Beams match by name, and a NIF quad gets the sum of the pulses of its four beams, on the union of their knots. Template beams absent from the file have no key. The beams at time t are with_pulses(beams, P, t; by = :beam) (with_pulses).

Briareus.read_visrad_pulse_shape — Method
read_visrad_pulse_shape(path) -> PulseShape

Read one of the standard laser pulse-shape files of VisRad (data/laser_pulse_shapes of the installation), a two-column ASCII table of power (W) versus time (s) (VR/files/laser_pulse_shape_files.html), and return it in ns and TW. The column order is not stated. Time first is an assumption, and the columns are swapped when the first column is not sorted while the second is. Non-numeric lines are skipped.

Briareus.read_visrad_sst — Method
read_visrad_sst(path; template = nif_beams(), absent = :off, units = nothing)
    -> Vector{Beam}

Read a NIF SST pointing CSV and apply it to template. The file may come from File | Export Laser Beam Data | NIF SST Beam Data in VisRad, from the SST, or from write_visrad_sst. Each beam found in the file gets its aim (mm, chamber Cartesian about TCC, defocus not applied) and defocus (mm), and power and spot are kept. As in the VisRad import (VR/power_sources/import_laser_beam_data_csv.html), template beams absent from the file are turned off (absent = :off, power 0). :keep leaves them unchanged, and :error throws.

Beam names match case-insensitively, with BL115 read as B115. With a quad template (nif_quads()), each quad takes the mean aim and defocus of its four beams, with a warning if they differ by more than 1 µm. The header row is found by its "Beam Aim Point" columns. Lines before it are skipped, and extra columns are ignored. Units come from the headers ("(mm)", "(cm)", "(um)"), and units (mm per file unit) overrides them.

Briareus.read_visrad_summary — Method
read_visrad_summary(path; template = nothing, absent = :off, spot_definition = :auto,
                    rotation_sense = :beam, angle_tol = 0.05) -> Vector{Beam}

Read a VisRad Laser Beam Summary CSV (Export Data in the Laser Beams Summary dialog, VR/power_sources/laser_summary_table.html; also written by write_visrad_summary). Columns are recognized by header, so older layouts and extra columns are accepted.

Conversions:

  • Pointing. "TC Pt Pos-x/y/z" (cm) is the focus of the beam in the target-chamber frame, which is the Reference Point plus the focus offset along the beam. This follows from the example table in the manual (VR/power_sources/images/laser_summary.jpg). Beams pointed at the same foil-frame Reference Point with focus offset -0.215 cm have TC positions that differ by exactly 0.215 cm × the difference of their port vectors. So aim = 10·TC + defocus·port (mm) with defocus = 10·focus offset (cm → mm). When the TC columns are absent, the Reference Point is taken from "Pt Param-1/2/3" (cm, as Cartesian, cylindrical (r, z, φ) or spherical (r, θ, φ) coordinates, with angles in degrees). This works only for references in the target-chamber frame ("Target Chamber" or "TCC"). When both are present they are cross-checked.
  • Power. "Power" is in TW, and for NIF it is the sum of the 3ω, 2ω and 1ω cones (VR/power_sources/nif_beam_params.html). Time-dependent beams show their peak as "T-<peak>", which is read as the peak with a warning. Off beams get power 0.
  • Spot. "R0" major/minor are radii (µm) at the spot-size definition level, "36.8% (1/e)", "50%" or "5%" of peak (VR/power_sources/set_laser_profile_props.html). They become the 1/e semi-axes a (major) and b (minor) of the same super-Gaussian exp(-[(x/a)²+(y/b)²]^(n/2)), which is the focal profile of VisRad. The definition comes from an "R0 Def" column if present, and otherwise from spot_definition. With :auto, the level of a recognized built-in phase plate is used (VISRAD_PHASE_PLATES; NIF CPP radii are HWHM), and 1/e otherwise. 1/e is the VisRad default for Custom Supergaussian and an assumption for other models. :e, :hwhm, :pct5 or a number set the level explicitly. The exponent n comes from an "SG Exponent" column, else from the phase-plate table, else from the template beam. A "Uniform" profile (flat across R0 at focus) is approximated by n = 50 with 1/e radius R0.
  • Rotation. "Rot Angle" is the minor-axis rotation ρ (degrees, clockwise from vertical; ρ = 0 puts the major axis "nearly horizontal"). The Briareus angle of the major axis from θ̂ toward φ̂ is 90° − ρ for rotation_sense = :beam (the spot seen along the beam) and 90° + ρ for :target (seen from TCC). The manual does not state which. The deposition of VisRad 21 settles it as :beam: at ρ = ±30°, 60° and 90° on ten NIF beams, its spot axes match :beam within 0.04° and differ from :target by 60°. Horizontal is φ̂ of the NIF quad port of the beam (quad of the template beam), which is turned 1.6–5.3° from φ̂ of the beam, as measured in VisRad 21 to 0.02° on 48 beams. Beams of no NIF quad use their φ̂.
  • DPR, halo, f-number and wavelength are not in the file. DPR "On" is ignored with a warning; VisRad splits such OMEGA beams into two cones 85 µm apart. The other values come from the template.

With a template, beams are matched by name, case-insensitively, with "BL115" read as "B115" and "10" and "BL-10" as "Beam_10". Port angles are checked against the "Polar Ang"/"Azm Ang" of the file, with a warning beyond angle_tol degrees, which indicates a frame or naming mismatch. Template beams absent from the file follow absent (:off, :keep, :error), since VisRad omits hidden unused beams. NIF quads aggregate their four beams, with the mean aim and defocus and the summed power. Without a template, beams are built from the port angles of the file.

Briareus.read_visrad_table — Method
read_visrad_table(path; header = nothing) -> (; header, labels, data)

Read a multi-column ASCII table exported by VisRad. The table is the Surface Element Properties table (File | Save Data for Object / All Objects / Selected Rows, and the *.sed files of a run; VR/results/display_surf_elem_table.html, VR/simulation_times/config_sim_params.html) or a Power Summary (*.psd). The manual shows the columns, for example "Z (cm)", "Azim. ang (deg)", "Radius (cm)", "Surf Index", "Emis T (eV)", "Rad T (eV)", "Flux In (TW/cm2)" and "Flux Out (TW/cm2)" (VR/results/images/surf_elem_table.jpg), but not the file layout. The reader is therefore tolerant (assumption throughout):

  • the table may be comma-, tab- or whitespace-separated;
  • data rows are the most common shape of lines ending in numbers, and any leading non-numeric text is kept as the label of the row (an object name);
  • the header is the last non-data line before the first data row. It is split on the delimiter, on runs of 2+ spaces, or by attaching "(unit)" tokens to the words before them.

When that fails, header (a vector of names for the numeric columns) sets the names.

Returns the numeric column names, row labels (empty strings when none) and an nrows × ncols matrix.

Briareus.visrad_legendre_fit — Method
visrad_legendre_fit(theta, values; terms = 0:4, weights = nothing) -> Vector

Least-squares fit f(θ) = Σₗ Aₗ Pₗ(cos θ) over the given terms, as in the Surface Element Statistics of VisRad, with coefficients up to A4 and each term selected by a check box (VR/results/display_surf_elem_table.html). theta is in degrees. The result A is indexed l+1, with zeros for unused terms, so A[3]/A[1] is P2/P0. The fit is unweighted by default, since the VisRad weighting is not documented (assumption); element areas passed as weights weight it. The same fit applied to Briareus and VisRad element values gives a like-for-like comparison.

Briareus.visrad_nif_spot — Method
visrad_nif_spot(cone) -> SuperGaussianSpot

The best-focus spot of the VisRad phase plate for a NIF cone (VISRAD_NIF_PLATES, visrad_spot at rotation 0), with the major axis along φ̂ of the port as for nif_spot. VisRad measures the rotation of the spot of a NIF beam from the horizontal of its quad, so the spots of the VisRad beams are nif_beams(; spot = visrad_nif_spot, spot_frame = :quad). With deposition_kw = (; profile = VisRadProfile()), the deposition follows the VisRad beam model (research notes, "VisRad deposition parity").

Briareus.visrad_spot — Method
visrad_spot(plate; rotation = 0.0, rotation_sense = :beam) -> SuperGaussianSpot

Briareus spot equivalent to a VisRad built-in phase plate, given by its VISRAD_PHASE_PLATES name or a CMT or summary-table spelling such as "Rev3 Inner Cone 2W CPP" or "OMEGA E-IDI-300 DPP". The tabulated radii, defined at the intensity level of the table, are converted to 1/e semi-axes (mm) of the same super-Gaussian, r_1/e = r_f / (ln(1/f))^(1/n). rotation is the minor-axis rotation of VisRad (degrees, clockwise from vertical, 0 with the major axis horizontal); see read_visrad_summary for rotation_sense.

Briareus.visrad_ylm_fit — Method
visrad_ylm_fit(theta, phi, values; lmax = 4, weights = nothing) -> Vector

Least-squares fit to the real spherical harmonics of VisRad (VR/results/display_surf_elem_table.html). These are Y_LM = N_LM P_L^M(cos θ) for M = 0 and √2 N_LM P_L^|M|(cos θ) × cos Mφ (M > 0) or sin |M|φ (M < 0), with N_LM = √((2L+1)(L−M)!/(L+M)!). Then Y_00 = 1, and A_00 is the mean; the example in the manual gives a mean of 9.736 and A_00 = 9.739. A_L0 = A_L/√(2L+1) for the Legendre A_L, and the same example gives 1.143·√5 = 2.556 against A_2 = 2.563. Angles are in degrees, and the coefficients are in the flat mode_index order of Briareus. They are the orthonormal ylm_moments of Briareus times √(4π). The manual does not state whether its P_L^M includes the Condon–Shortley phase. No phase is assumed, so the signs of odd-M coefficients may flip; √(Σ_M A_LM²)/A_00 is unaffected.

Briareus.write_visrad_kit — Method
write_visrad_kit(dir, target, beams; model = nothing, op = nothing, pulses = nothing, by = :group,
                 time = 0.0, observe = :capsule, terms = (0, 2, 4), lmax = 4,
                 rotation_sense = :beam, notes = "") -> NamedTuple

Write everything needed to rebuild a Briareus case in VisRad, together with the Briareus results for comparison (compare_visrad), into directory dir:

  • pointing_sst.csv — per-beam pointing in the NIF SST format (write_visrad_sst), imported with File | Import Laser Beam Data | Pointing Data, Custom CSV, units mm.
  • beam_summary.csv — the full beam set in Laser Beam Summary layout (write_visrad_summary): port angles, pointing, focus, power, 1/e spot radii, exponents and rotations.
  • powers.csv — per-beam time-dependent powers (write_visrad_powers), when pulses is given (keyed by, as in write_visrad_powers); beam powers are then evaluated at time.
  • briareus_beams.csv — the canonical Briareus beam table (write_beam_table).
  • README.txt — target geometry (component shapes and dimensions in mm, cm and µm, materials, albedos and conversion efficiencies), beam settings, and the VisRad steps.
  • briareus_results.csv — quantity,value,unit rows: per-component "Laser Pwr Dep", "Pwr Src Term" (conversion × laser), "Incident Rad Pwr" (Σ H·A), "Emitted Rad Pwr" (Σ B·A), all TW, and "Surface Area" (cm²), named as the Power Summary columns of VisRad; the laser power that misses or strikes outer surfaces; and for observe the mean incident flux (TW/cm²), the VisRad-style Legendre fit (visrad_legendre_fit over terms) and per-L amplitudes of the VisRad spherical-harmonic fit (visrad_ylm_fit).
  • briareus_<observe>_elements.csv — per-element polar and azimuthal angle about the center of the component (degrees), area (cm²), incident flux and absorbed laser flux (TW/cm²).

The deposition uses op (default DepositionOperator(target, beams)) and the radiation model (default RadiationModel(target)). Returns (; dir, files, results) with results a Dict of the quantities in briareus_results.csv.

Briareus.write_visrad_powers — Method
write_visrad_powers(path, beams, pulses; by = :group, times = nothing) -> path
write_visrad_powers(path, pulses::AbstractDict{Symbol,PulseShape}; times = nothing) -> path

Write a VisRad time-dependent beam-power CSV (VR/files/laser_beam_data_files.html). The header is time (ns), followed by one column per beam named as VisRad names beams (B115 for NIF, Beam_10 for OMEGA), and the rows hold time (ns) and power (TW per beam). The file is imported with File | Import Laser Beam Data | Time-Dependent Powers (VR/power_sources/import_tdep_beam_powers.html). For NIF, VisRad assigns the powers to the 3ω (blue) cones.

pulses takes the forms of with_pulses: a PulseShape for every beam, or a Dict/NamedTuple keyed by group (default), quad, beam name (by = :beam, as read_visrad_powers returns them) or a function of the beam. The second form writes a Dict keyed by beam name as it is. NIF quads expand to their four beams at a quarter of the quad power each. Times default to the union of all pulse knots, so piecewise-linear pulses are reproduced exactly when each starts and ends at zero power. A PulseShape is zero outside its table, so a pulse that starts or ends at a finite power gets a ramp to the knots of its neighbors instead. Briareus beam names that are not facility names, such as the hohlraum-frame B01… of omega_beams(), are written as they are and should be renamed first.

Briareus.write_visrad_sst — Method
write_visrad_sst(path, beams; include_off = false) -> path

Write beam pointing as a NIF SST CSV (VISRAD_SST_COLUMNS). The file has one row per NIF beam ("B111"–"B468"), with the aim point in target-chamber Cartesian coordinates about TCC (mm) without the defocus applied, and the defocus (mm; a positive defocus moves the focus along the propagation direction). This is the export format of VisRad (VR/files/laser_beam_data_files.html, "NIF SST Data Files"). It imports into VisRad through File | Import Laser Beam Data | Pointing Data, "Custom" CSV, which recognizes these headers (VR/power_sources/import_laser_beam_data_csv.html).

NIF quads (names "Q11T"…, e.g. nif_quads()) are written as their four beams with the pointing of the quad. VisRad turns on exactly the beams that have pointing data, so beams with zero power are left out unless include_off.

The file does not contain powers or spots. It is paired with write_visrad_powers, and the spot model is set in VisRad (see write_visrad_kit).

Briareus.write_visrad_summary — Method
write_visrad_summary(path, beams; rotation_sense = :beam, cluster = b -> string(b.group),
                     profile = "Custom Supergaussian", extras = true) -> path

Write beams in the layout of the VisRad Laser Beam Summary CSV, one row per VisRad beam. NIF quads expand to their four beams with a quarter of the power each. The columns are the cluster, beam ID, on/off (power > 0), port polar angle and azimuth (degrees), the pointing reference "Target Chamber"/"Cartesian" with the aim as Pt Param-1/2/3 (cm), the focus offset (cm), the focus position "TC Pt Pos" (cm, aim + defocus·k), the power (TW), DPR "Off", the spatial profile model, R0 major/minor as 1/e radii (µm), and the minor-axis rotation (degrees; see read_visrad_summary for rotation_sense). extras appends "SG Exponent" and "R0 Def" ("36.8% (1/e)") so that the file is self-contained.

Columns through "TC Pt Pos-z" reproduce the headers of the v21 dialog. The names of the later columns are not shown in the manual (assumption), and halo parameters are not written, since VisRad has none. The file serves for records and for read_visrad_summary. Pointing is set in VisRad by importing the output of write_visrad_sst, whose format is documented.

Briareus.VisRadObject — Type
VisRadObject

One target component of a VisRad workspace, as read by read_visrad_workspace.

Fields: name; VisRad's object type code and the kind Briareus recognizes (:mesh for CAD/generalized meshes, :sphere, :rectangle, :cylindrical_hohlraum, :other); the folder path in VisRad's component tree ("" at the top); params, every key = value line of the object verbatim; rotation and position (mm), the object frame in the target-chamber frame (x_chamber = rotation * x_object + position); mesh, the surface in the chamber frame (mm) for meshes (one patch per VisRad surface element) and nothing otherwise; albedo, conversion (x-ray conversion efficiency) and reflectivity (laser); the flags radiosity, laser (direct laser deposition) and visible; and color (RGB in [0, 1]).

Briareus.read_visrad_workspace — Method
read_visrad_workspace(path; template = nothing, absent = :off, spot_definition = :auto,
                      rotation_sense = :beam, angle_tol = 0.05) -> VisRadWorkspace

Read a VisRad workspace (.vrw) with its target components, including CAD imported as generalized meshes, and its laser beams. Both of VisRad's formats are read: the text format of VisRad 20–21 ("Workspace Format ID = 11") and the JSON format VisRad 21 writes when it saves a computed workspace ("Workspace Format ID": 1001). The two formats contain the same objects, meshes, beam rows and beams, except that the JSON file stores the beam port angles and f-numbers to full precision (the text table rounds them to 3 decimals) and colors to 6 digits. Lengths are converted from cm to mm; every object and beam frame is resolved to the target-chamber frame. Build a Briareus target from the components with visrad_target.

Components become VisRadObjects. CAD meshes keep VisRad's surface elements as patches (one per triangle). Spheres, rectangles and cylindrical hohlraums are meshed on VisRad's grid when converted by visrad_target. Objects are placed by VisRad's orientation angles and position (VR/grid/specifying_orient_angles.html), relative to the chamber or to another component. The parameters that set the geometry and material of an object (its position, coordinate type and orientation angles, the lengths and mesh counts its primitive uses, the albedo, conversion and reflectivity values, and the radiosity and laser-deposition flags) are required: a missing or malformed one throws an ArgumentError naming the key and the object. Flags that only modify (normals flipped, wall thickness, time-dependent models, the key-point reference) default to 0, visibility to on and the color to gray; a malformed value of any key throws.

Beams. Port angles and f-number come from the file. Pointing at TCC or at a point given in the chamber frame or a component frame is supported; the point becomes the aim and the focus offset (cm) becomes the defocus (mm), as in read_visrad_summary. Power is the 3ω (blue cone) power in TW for beams with 3ω on, and 0 otherwise. It is the power column times the beam power multiplier when enabled and, under VisRad's "Fraction of Total Beam Power" red/green model, where that column is the total, also times $1 - f_G - f_R$. Spots are VisRad's super-Gaussian radii (µm), exponent and minor-axis rotation, converted as in read_visrad_summary. Radii that match a built-in phase plate (VISRAD_PHASE_PLATES) are taken at the level of that plate (HWHM for NIF CPPs) and other radii at spot_definition (:auto = 1/e). The rotation of a NIF beam is relative to the horizontal of its quad; the quad comes from the template or, without one, from the beam name. Unconverted light, time-dependent powers, energy normalization and DPR are warned about and not imported.

With a template (e.g. nif_beams()), the pointing, power and spots in the file are applied to the template beams by name, and their other properties (halo, wavelength, quad, group) are kept; port angles are checked to angle_tol degrees and absent handles template beams missing from the file, as in read_visrad_summary. Without one, beams are built from the file, grouped by VisRad cluster.

Briareus.visrad_component — Method
visrad_component(object; material = nothing, two_sided = false, orient = false,
                 toward = (0, 0, 0), coarsen = nothing, remesh = nothing,
                 fit = remesh !== nothing, primitive_h = nothing) -> Vector{Component}

Briareus components for one VisRadObject, in the chamber frame (mm). The material defaults to the albedo and x-ray conversion efficiency of the object. A CAD mesh becomes one component radiating from the front of VisRad's surface elements (counterclockwise winding, assumption), or from both sides when two_sided. VisRad does not let users edit the normals of imported CAD (VR/grid/import_export_cad_files.html), and tessellated CAD often faces the wrong way: in the NIF workspace this reader was built from, the inner hohlraum wall faces away from the cavity. orient = true repairs the winding with orient_mesh, so that it is consistent across shared edges, closed solids face out of their material and open sheets face the point toward (mm, chamber frame; by default the target chamber center). With two_sided = true the surfaces instead radiate from both sides, and thin shells are then modeled as two radiating sides. CAD needs fewer, compact elements before view factors: remesh (mm) divides the surface into near-planar elements of about that size whatever the facet shapes (remesh_mesh; long slivers are cut), while coarsen (mm) only merges whole near-coplanar facets up to that size (coarsen_mesh; slivers longer than the size stay). fit is on by default with remesh, or is a named tuple of curved_components and fit_surfaces keywords. It then splits a remeshed CAD part into its cylinders, cones and spheres and the rest (curved_components). Each curved piece is given its exact surface fitted to the CAD facets, and curved faces of under 10⁻³ of the part area stay flat unless minfraction = 0. The radiation model then integrates on the curved walls as it does for a primitive hohlraum. The pieces, <name>/cyl1, …, <name>/rest, keep the object name as their part, which the name-taking functions and reports use (see cad_target); fit = false keeps one flat component.

A rectangle becomes one component (normal +z before orientation) and a sphere one with a SphereSurface. A cylindrical hohlraum becomes five components, <name>_wall, _cap_top, _cap_bottom and the apertures _leh_top and _leh_bottom, with the curved surfaces hohlraum uses. All are meshed on VisRad's grid (Number of mesh pts, which reproduces VisRad's element table), or with primitive_h (mm) on Briareus's grid for elements of about that size (hohlraum_counts, capsule_counts), e.g. to resolve a spot on a foil that VisRad meshes coarsely. No components are made for other object types, and a warning is issued.

Briareus.visrad_deposition — Function
visrad_deposition(workspace, target = visrad_target(workspace);
                  sources = visrad_power_sources(workspace)) -> Vector{Float64}

VisRad's absorbed laser power per element of target (TW), from the direct laser power source of a computed workspace (visrad_power_sources). Each value is the source of a VisRad surface element (TW/cm²) times its area. This is the convention of deposit(...).element, so VisRad's and Briareus's depositions on the same target compare per element and per component (sum(P[elements(target, :wall)])).

target must hold the workspace objects as visrad_target(workspace) or visrad_component build them, one component per object (named after it) on the VisRad elements. Each component is checked against the elements of its object, and a component remeshed, coarsened, fitted or cut to a cavity is refused. The target compared with VisRad is therefore not the remeshed target of a radiation study (see visrad_target): build both from the workspace, and compare depositions on this one. Elements are matched as follows.

  • A CAD mesh (generalized mesh) has one Briareus patch per VisRad surface element, in the connectivity order of the file. The order is that of VisRad. It is confirmed by Briareus's deposition matching VisRad's at every element (correlation 1.0000, 0.9% rms with VisRadProfile) on 2388 wall elements of a NIF workspace.
  • On a rectangle on VisRad's grid, VisRad's elements run the local x fastest (measured on a foil workspace).
  • On spheres and cylindrical hohlraums, VisRad's element order is not established; only the counts are. An object of these kinds with any laser power is refused; leave it out of the target (visrad_target(ws; select)) to map the rest.

On a two-sided component the power is assigned to its front elements (VisRad's table has one value per surface element). Objects with laser power but no component in target are warned about; components without a VisRad table stay zero.

Briareus.visrad_power_sources — Method
visrad_power_sources(workspace; stale = :error) -> (; time, units, tables)

VisRad's power-source results saved in a computed workspace (a .vrw path or a VisRadWorkspace, re-read from its path), taken from the [Power Source Data] section that VisRad writes after computing the power sources. Per object it lists one row per surface element: index (0-based), direct laser power source (TW/cm², the laser power absorbed per area averaged over the element), uniform source, albedo, x-ray conversion efficiency, laser reflectivity, pre-reflection laser power, numbers of red and blue cones hitting the element, and minimum overlap angles at 1ω and 3ω.

tables maps each object name to a NamedTuple of column vectors, named from the section header (:surface_index, :direct_laser_pwr_source, :uniform_source, :albedo, :x_ray_conv_efficiency, :laser_reflectivity, :pre_reflect_laser_pwr, :n_red_cones_hitting_surf, :n_blue_cones_hitting_surf, :min_angle_overlap_1w, :min_angle_overlap_3w in VisRad 20–21); integer columns are Int. units maps column names to the header units ("TW/cm2", "deg", ""), and time is the simulation time (ns) the sources were computed for.

A workspace saved before computing, or changed since, shows "Power sources are not up to date" and has no tables: that is an error, or nothing with stale = :nothing. Tables of the same layout in other sections (beam capture and clearance data) are not read. Map the direct laser source onto a Briareus target with visrad_deposition.

JSON workspaces (VisRad 21's format for a computed workspace) contain the same tables. Their "Power source data" lists the objects in the order of the target components without names, with values at full precision (the text table rounds the direct source to 5 decimals, 5 × 10⁻⁷ relative on a NIF wall).

Briareus.visrad_target — Method
visrad_target(workspace; select = o -> o.radiosity || o.laser, materials = Dict(),
              two_sided = false, orient = false, toward = (0, 0, 0),
              coarsen = nothing, remesh = nothing, fit = remesh !== nothing,
              inside = nothing, visibility = :sampled, closed = false) -> Target

Target built from the components of a VisRad workspace (read_visrad_workspace) for which select(object) is true — by default those that VisRad includes in its radiosity or direct-laser calculation. materials maps object names (Strings or Symbols) to a Material overriding the albedo and conversion efficiency in the file; a name that is not an object of the workspace is an error. two_sided (a Bool, or a function of the object) makes surfaces radiate from both sides; see visrad_component for why CAD meshes often need it, and for orient, toward, remesh, coarsen and fit. These apply to CAD meshes and give repaired windings, elements of about remesh or coarsen mm, and exact cylinders, cones and spheres for the radiation model.

CAD meshes can hold hundreds of thousands of triangles, and each becomes a radiating element. That is fine for ray tracing, as in deposition, clearance and imaging, but too many for view factors; select the parts that matter for the radiation problem, e.g. select = o -> o.folder == "Hohlraum" or by name, and remesh them. inside, a point (mm, chamber frame) in the cavity, keeps only the elements that bound the free space around it, as enclosure does with its defaults; enclosure called on the full target gives the options and a per-component account of what was dropped. It needs consistent windings (orient = true). The selection runs on the CAD facets as oriented. remesh or coarsen then divides only the facets kept (much cheaper when most of the assembly lies outside the cavity), and a second selection on the resulting elements drops those that average too little flux. fit then applies to the elements kept and fits them on the kept facets. The CAD meshes go through these steps in cad_target, which takes the other components as they are (into the selection, but not remeshed or fitted); it does the same for CAD read from STL files. visibility is the default view_factors visibility rule of the target. It is :sampled, as for cad_target, because workspaces contain entrance-hole washers and CAD with rims. closed = true declares the target a closed enclosure (balanced view factors), as for cad_target; it applies only when apertures close every opening (see open_fraction).

Two targets from the same workspace are usually built, one for a comparison with VisRad and one for a radiation study. visrad_deposition maps VisRad's per-element deposition only onto components on the VisRad elements, so it takes a target built without remesh, coarsen, fit and inside (e.g. visrad_target(ws), with the same select). On that target a DepositionOperator reproduces VisRad's calculation per element, and the view factors are computed on the remeshed, cut target. The same beams are used for both, with one DepositionOperator per target.

Briareus.write_visrad_workspace — Method
write_visrad_workspace(path, template, beams; angle_tol = 0.05, overwrite = false) -> path

A VisRad workspace with the pointing, focus, power and on/off of beams written into a copy of the workspace template (a .vrw file, e.g. the one a design was imported from with read_visrad_workspace). Each beam row of the template whose name matches a beam is given the aim of that beam, as a Cartesian position in the reference frame of the row (cm), its focus offset defocus (cm), its power as the 3ω power column (divided by the power multipliers of the row and, under the "Fraction of Total Beam Power" red/green model, by its blue fraction, so that the beam power is in VisRad's blue cone) and on (power > 0) or off. Everything else is copied verbatim: the target components and their frames, the spots, pulse shapes and VisRad's settings stay as the template has them. Numbers are written in place at the column widths and decimals of the template (0.1 µm for positions).

The results of a computed template (power sources, radiosities, beam capture and clearance) are reset to "not up to date" when any row is written: they belong to the old beams. The template must be a text workspace: VisRad 21 saves computed workspaces as JSON, which is read (read_visrad_workspace) but not patched.

A path that already contains VisRad's results — a JSON workspace, or a text one with power sources or radiosities up to date, including the template itself — is refused unless overwrite = true: those results exist only in that file.

Rows without a matching beam are left as they were, and beams without a row are reported in a warning: the template defines which beams exist. A beam whose port differs from the port of its row by more than angle_tol degrees is refused (ports cannot be changed). Time-dependent power tables and energy normalization in the template are left as they are, so a row that uses them does not take the constant power (with a warning).

Briareus.compare_visrad — Method
compare_visrad(workspace, sol; elements = Dict(), sources = visrad_power_sources(workspace; stale = :nothing),
               observe = :capsule, lmax = 4, center = nothing, index_base = nothing, io = nothing)
    -> (; rows, elements)

Compares a Briareus radiation solution sol with VisRad's results for the same workspace, per element. sol is solved on a target with the VisRad elements, from visrad_target(workspace) or a selection of its objects (see visrad_deposition). The solve can start from the VisRad deposition, as in solve(RadiationModel(t), visrad_deposition(workspace, t)), to isolate the radiation solve, or from the Briareus deposition. Three comparisons are made:

  • Laser deposition comes from the power sources of the workspace, sources, and nothing skips it. Per object, the rows give the absorbed power ("Laser Pwr Dep", TW) as Σ source × area against sol.laser. They also give the per-element agreement of the absorbed flux (TW/cm²) on the elements that either side lights.
  • elements holds VisRad's Surface Element Properties export per object, as a Dict from object names to paths or read_visrad_table tables, mapped as in visrad_element_values. Each column of the table among "Flux In" (sol.H), "Flux Out" (sol.B), "Rad T" and "Emis T" is compared per element on the elements that the table lists; "Rad T" and "Emis T" are the radiation temperatures of H and B. Per object, rows are added for the incident and emitted powers ("Incident Rad Pwr", "Emitted Rad Pwr"), Σ flux × area in TW. A row is also added for "Rad T", the radiation temperature (eV) of the area-mean incident flux. Each of these rows uses the elements that both sides have.
  • observe names the component whose incident flux is analyzed in spherical harmonics, such as the capsule. Both sides use the same exact solid-angle weights (ylm_weights to lmax, about center). center defaults to the object position, the origin of the VisRad angles for that object; for a CAD mesh it is the bounding-box center. The rows are "P2/P0" and so on, the m = 0 coefficient as a Legendre ratio aₗ/a₀. Rows "mode amplitude l=2" and so on give √((2l+1) Σₘ cₗₘ²) / c₀₀ for the orthonormal coefficients cₗₘ, which is |aₗ/a₀| for an axisymmetric field. All modes for l = 1, …, lmax are in percent. The analysis needs the "Flux In" of that object over all its elements. A table that VisRad fits itself (Analysis | Statistics) fits element centroids by least squares (visrad_ylm_fit). The weights in compare_visrad integrate the solid angle of each element exactly, so both sides are analyzed alike.

Returns rows and elements. rows holds (; quantity, unit, briareus, visrad, difference, relative) entries, as the kit form of compare_visrad gives them, with modes in percent. elements holds one (; object, quantity, unit, n, briareus, visrad, rms, max, correlation) per object and quantity. Its fields are the area-weighted means of both sides, the area-weighted rms and the largest absolute difference as fractions of VisRad's mean, and the area-weighted correlation. Both are printed to io when given.

Briareus.visrad_element_values — Method
visrad_element_values(workspace, target, tables, column; index_base = nothing) -> Vector{Float64}

Maps one column of VisRad's per-element results onto the elements of target. The target must be built on the VisRad elements, from visrad_target(workspace) or a selection of its objects without remesh, coarsen, fit or inside. visrad_deposition describes the element orders that result. tables maps object names to VisRad's Surface Element Properties export of that object, which is saved with File | Save Data for Object or as the *.sed file of a run. Each entry is a path, or a table as read_visrad_table returns it. column is a Regex matched against the table header (e.g. r"flux\s*out"i, r"rad\s*t"i).

Rows are matched to VisRad's surface elements by the "Surf Index" column of the table, which may list a subset in any order. Without that column the rows must be the elements of the object in order. VisRad does not document whether the index counts from 0, as in the power-source tables of the workspace, or from 1 (assumption). With index_base = nothing, the base is 0 when an index is 0 and 1 when the largest index equals the element count; otherwise an ArgumentError is thrown. Pass index_base = 0 or 1 to fix it. Fluxes, with headers in TW/cm², TW/mm² or W/cm², are converted to the Briareus unit TW/mm², the unit of H and B in a RadiationSolution. Other columns, such as temperatures in eV, are returned as they are. A two-sided component takes the values on its front elements. Elements without a value are NaN. An object named in tables that is not in the workspace throws an error, and one without a component in target is skipped with a warning.
