Diagnostic definitions

A synthetic diagnostic is described by a definition file: one TOML file per instrument, holding its line of sight, its hardware and its recording, each value with its source. The public definitions ship with the package (data/diagnostics); a user group keeps separate definitions, including details that are not public, in directories on a search path, and modifies a public definition by extending it; the public file is not copied. diagnostic builds the instrument of a definition (for the soft x-ray power kind, a DanteView for dante); check_diagnostics reports every problem in the files on the search path, by file and key.

The search path

diagnostic_paths lists the directories read, in order of precedence: the built-in definitions, the directories saved in the user configuration file (diagnostic_config_path, key diagnostics.paths), those of the environment variable BRIAREUS_DIAGNOSTICS (for batch jobs; ;-separated on Windows, :-separated elsewhere) and those added for the current session. Directories are read recursively. A definition later on the path shadows an earlier one with the same id, with a warning naming both files. A directory is added once and kept for later sessions with

add_diagnostic_path("//groupserver/briareus/diagnostics")

and remove_diagnostic_path removes it. The built-in constructors (dante1, dante1_responses) read the built-in definitions only, so user files do not change them; diagnostic("nif_dante1") takes the search path.

A definition file

Every file has a header: schema (the format version, DIAGNOSTIC_SCHEMA), id, and either kind or extends; optionally name, facility, instrument, public (false for non-public detail), valid_from and valid_to (dates), shots, and the source keys source, confidence (H, M or L, as in the research notes) and note, which every table may also carry. instrument names the instrument a definition is one configuration of: the Dante 1 channel sets of several years and shots all carry instrument = "NIF Dante 1", and a file that extends one of them inherits it (diagnostic_instrument). A list of diagnostics, such as the Diagnostics tab of the desktop application, shows each instrument once for the facility of the session and offers its definitions as configurations. Keys are checked: an unknown key or a value of the wrong type is an error naming the file and the key. Units are in the key names (theta_deg, energy_eV, thickness_um, solid_angle_sr).

The kind radiography, for backlit radiographs of an area backlighter imaged through a pinhole or by point projection, builds a Radiograph for radiograph, which takes the target with its backlighter foil, the laser deposition on the foil and the parts of the object with their materials. It takes:

The images are of detected photons per mm² of detector, with the open field (no object) and the transmission that a radiograph normalized by it measures; the frames of a gated radiograph are the emission recorded through each gate.

A field of view takes in every surface of the target facing the instrument, occluded by any part: a NIF Dante's is ±30 mm at TCC (the 2004 design), wider than any hohlraum, so windows, packages and shields enter the signal as they would on the shot. Within an extended definition, giving one of area_mm2 / area_part, center_part / center_mm or port / theta_deg and phi_deg drops the other inherited from the base.

The response of a channel is the product of its parts (DanteResponse). Measured curves are CSV files with a header line and two columns, photon energy (eV) and value (a fraction, or V/GW for a sensitivity or a response), at a path relative to the definition file (TabulatedCurve); outside a table a factor keeps its end values and a whole response is zero, and check_diagnostics warns when a table does not cover 50 eV – 20 keV.

Extending a definition

A file with extends = "<id>" takes that definition and replaces what it gives: tables per key, channels by number (the keys listed for a channel replace those of the base channel; a new number adds a channel), and remove_channels drops channels. A campaign that replaced Dante 1's channel 6 filter, removed channel 16 and added a calibrated channel is, in full:

schema = 1
id = "group_dante1_campaign"
extends = "nif_dante1"
name = "Dante 1, campaign configuration"
public = false
remove_channels = [16]

[[channel]]
number = 6
filters = [{ material = "Cu", thickness_um = 1.1 }]
source = "campaign shot sheet"

[[channel]]
number = 19
energy_eV = 1000
solid_angle_sr = 6.5e-7
response_csv = "calibrations/ch19.csv"

DiagnosticDefinition.chain lists the files a definition was resolved from, and public is false when any of them sets public = false. Values a definition lacks to be built (Dante 2's channels are not public, for example) are reported as :missing by check_diagnostics, with the key to supply.

Definitions in sessions

A saved GUI session contains the definitions of the diagnostics it records, so that it records the same instruments on any computer. diagnostic_table writes a resolved definition as one standalone table, without extends and with each CSV path mapped, for example to a copy stored beside it. diagnostic_definition reads such a table back and checks it as a file on the search path is checked. diagnostic_diff lists the keys in which two definitions differ, with CSV files compared by content. When a session is opened, a saved definition that differs from the definition of the same id on the search path is reported with those keys, and the saved one is used unless the one on the search path is chosen.

New kinds

register_diagnostic_kind adds a kind: a schema of DiagnosticFields and a builder. The format already reserves the recording modes of the kinds planned next (time-integrated, gated and streaked imagers, radiography, streaked optical diagnostics); see reference/diagnostics-design.md in the repository.

Briareus.DiagnosticDefinition — Type
DiagnosticDefinition

A diagnostic definition read from a file and resolved through extends. The fields are id, name, kind, file (the file that defines it), chain (the files from which it was resolved, the base first), public and data. public is false when any file in the chain sets public = false, and data is the resolved table with CSV paths made absolute. diagnostic builds the instrument.

data["instrument"], when a file of the chain gives it, names the instrument of which the definition is one configuration. For example, the channel sets of NIF Dante 1 for several years and shots share instrument = "NIF Dante 1". A definition that extends another inherits the key, and a definition without it is a separate instrument (diagnostic_instrument).

Briareus.DiagnosticField — Type
DiagnosticField(type; required = false, doc = "")

One key of the schema of a diagnostic kind (register_diagnostic_kind). type is Real, Integer, String, Bool, :date, Vector{String}, Vector{Real}, a schema table (a Dict{String,DiagnosticField}) or a one-element vector that contains a schema table (an array of tables). Keys ending in _csv name a CSV file, as a path relative to the definition file.

source
Briareus.DiagnosticIssue — Type
DiagnosticIssue

A problem found in a definition file (check_diagnostics), with fields file, key (the path to the value, e.g. channel[6].filters[1].thickness_um), message and level. level is :error when the file cannot be used, :missing for a value that the definition lacks to be built (e.g. one that is not public), or :warning.

Briareus.add_diagnostic_path — Method
add_diagnostic_path(dir; save = true) -> Vector{String}

Add the directory dir to the diagnostic search path, after those already on it. With save = true, the directory is stored in the configuration file (diagnostic_config_path), so later sessions find it. With save = false, it is added only for this Julia session. Returns the search path (diagnostic_paths).

source
Briareus.check_diagnostics — Method
check_diagnostics(; paths = diagnostic_paths()) -> Vector{DiagnosticIssue}

Read every definition on paths, resolve extends, check each definition against the schema of its kind and build it, and return the problems found (DiagnosticIssue). The problems are errors (unknown keys, wrong types, unreadable CSV files, unknown materials), values that a definition lacks to be built (:missing) and warnings (shadowed ids, CSV tables that do not cover the energy range of a channel). An empty result means that every definition builds.

Build the instrument of definition id found on paths (diagnostics), or of def, such as a DanteView for kind = "xray_power". kwargs go to the builder of the kind, for xray_power those of DanteView such as pixels, and replace the values of the definition. Briareus.XrayImager — Type
XrayImager(theta, phi; pinhole, distance, magnification, width, pixels = 256,
           center = 0, up = ẑ, filters = (), tables = (), mirror = nothing,
           detector = nothing, detector_pixel = 0.0, energy = nothing,
           mode = :integrated, times = Float64[], gate = 0.0, gate_shape = :gaussian)

A pinhole x-ray imager on the line of sight (θ, φ), in degrees, from target chamber center toward the instrument. A pinhole of diameter pinhole (mm) at distance (mm) from the object images at magnification onto a detector of pixel detector_pixel (mm). The object plane is sampled over a width × width mm field about center (a point, or the name of a part) on pixels × pixels rays. up (a chamber direction) is the up direction of the image.

The spectral response R(E) is the product of the filters, an optional mirror and the absorption of the detector. The filters are filter_transmission materials with thicknesses in mm, as for DanteResponse, and measured tables, and the mirror is as for DanteResponse. detector = (:Si, 0.015) absorbs 1 − e^{−μρt} of the photons in 15 µm of Si (no dead layer), a TabulatedCurve is a measured efficiency, and nothing absorbs every photon. R is a fraction, so images are of detected x-ray energy.

The point-spread function on the object plane is the geometric penumbra of the pinhole, a uniform disk of diameter penumbra = d(1 + 1/M). It is convolved with a Gaussian of the summed variances of the Fraunhofer diffraction of the pinhole (FWHM diffraction = 1.03 λ distance / d at photon energy, eV) and of the detector pixel (a box of detector_pixel / M). The Gaussian is an engineering approximation, since the Airy pattern and the box are not Gaussian, and a pinhole whose Fresnel number d² / λz is near 1 is not in the far field. energy defaults to the mean photon energy of the light that the imager detects from a 300 eV Planckian, an engineering default; a definition file states the value.

mode is :integrated for one image of the time integral, or :gated for one frame per time of times (ns). Each gated frame is the integral of the image against a gate of FWHM gate ns, :gaussian or :square, of peak 1.

source
Briareus.detected_radiance — Method
detected_radiance(im::XrayImager, B::AbstractVector) -> Vector{Float64}
detected_radiance(im::XrayImager, sol::RadiationSolution) -> Vector{Float64}
detected_radiance(im::XrayImager, s::SpectralSolution) -> Vector{Float64}

The radiance of each element that the imager detects (TW mm⁻² sr⁻¹ of detected x-ray energy), B ⟨R⟩ / π. It is the Lambertian radiance of the element times the response of the imager averaged over its spectrum. For a gray radiosity B (TW/mm²), the spectrum is the Planckian at the brightness temperature (B/σ)^{1/4} of the element. This is an assumption, since the reflected part of the radiosity has the incident spectrum. For a SpectralSolution, the radiosity of each group is used with the Planckian of the wall temperature of the element within the group.

imager_image(im::XrayImager, t::Target, L::AbstractVector) -> Matrix{Float64}
imager_image(im::XrayImager, sol) -> Matrix{Float64}

The image on the object plane (row 1 at the top, up) of the per-element detected radiance L (detected_radiance), blurred by the resolution of the imager, in TW mm⁻² sr⁻¹ of detected x-ray energy. For a solution, the target of the solution and detected_radiance(im, sol) are used.

Briareus.imager_record — Method
imager_record(im::XrayImager, t::Target, time, L::AbstractMatrix) -> NamedTuple

The record of a history by the imager. L is the detected radiance per element (rows) at each time of time (ns, columns), the detected_radiance of each step, taken as linear between the times. The result is (; images, times). For mode = :integrated it holds one image of the time integral (kJ mm⁻² sr⁻¹, as TW·ns), with times empty. Briareus.Radiograph — Type
Radiograph(theta, phi; line, distance, pinhole = nothing, pinhole_distance = nothing,
           width, pixels = 128, center = 0, up = ẑ, filters = (), tables = (),
           detector = nothing, detector_pixel = 0.0, foil = :backlighter,
           angular = :isotropic, prepulse = false, ce = nothing, irradiance = :mean,
           pulse, start = 0.0, mode = :integrated, times = Float64[], gate = 0.0,
           gate_shape = :gaussian)

A backlit radiograph on the line of sight (θ, φ), in degrees, from the object toward the detector. It records the He-α line (an element Symbol of kshell_line_energy, or keV) of the backlighter foil, a part of the target behind the object. The detector lies distance mm from center, which is a point or the name of a part. The object plane is a width × width mm field about center normal to the line of sight, sampled on pixels × pixels points, and it is the coordinate system of the image. up (a chamber direction) is the up direction of the image.

The optic is one of:

  • Pinhole imaging (pinhole, diameter mm, at pinhole_distance p mm from center): each image point views the foil through the pinhole and the object point, at magnification M = (distance − p)/p. The point-spread function is that of the x-ray imager (XrayImager). It combines the penumbra d(1 + 1/M) and a Gaussian of the diffraction at the line energy and the detector pixel, on the object plane.
  • Point projection (pinhole = nothing): each detector point receives every foil element as a point source at its centroid, along its path through the object. The extent of the source therefore blurs the image, by the source width × L/(s + L) on the object plane, with s the distance of the foil behind the object and L = distance. The image point of a detector point is where its line to the centroid of the foil crosses the object plane, and M = (s + L)/s. Only the detector pixel adds further blur.

The detector is flat and normal to the line of sight, and images are per mm² of it. A pinhole is taken as a thin disk normal to the line of sight, of area A = π(d/2)². An image point at ρ from center views the foil along a ray at the angle α to the line of sight, tan α = ρ/p, with radiance R. The étendue between the pinhole and a detector area dA_d at the end of the ray is A cos α · dA_d cos α / D², with D = (L − p)/cos α the pinhole–detector distance along the ray. The fluence is therefore R A cos⁴α/(L − p)², the on-axis value times cos⁴α. The factor combines the projected pinhole area, the inverse square of the longer distance and the incidence cosine on the detector. In point projection, the fluence E_e f(cos θ)/(4π r²) of each foil element, at its distance r from the detector point, is multiplied by the incidence cosine of the ray on the detector, r̂ · d̂. On the axis the pinhole factor is exactly 1. In point projection the incidence cosines differ from 1 by the angular extent of the source, at most (w/2)²/(2(s + L)²) for a foil of width w. Fluence normal to each ray, as backlighter_signal gives it, has none of these factors.

The spectral response at the line is the product of the transmission of the filters, the measured tables (TabulatedCurves, eV) and the efficiency of the detector. The filters are filter_transmission materials with thicknesses in mm, with the NIST tables where they cover the material and energy, as for backlighter_signal. detector = (:Si, 0.015) absorbs 1 − e^{−μρt} (Henke photoabsorption, no dead layer), a TabulatedCurve is a measured efficiency, and nothing absorbs every photon. rg.filter_transmission and rg.efficiency contain the two values at the line. Images are of detected photons.

The source is that of backlighter_signal, with prepulse, ce, irradiance and angular as there. It is the He-α energy of each foil element, emitted uniformly over the flat-top laser pulse of pulse ns from start ns, on the assumption that the emission follows the laser. mode is :integrated for the whole emission, or :gated for one frame per time of times (ns). Each gated frame records the emission against a gate of FWHM gate ns, :gaussian or :square, of peak 1, as in imager_record. The object is static over the emission, so a moving object needs one radiograph per frame of its geometry.

source
Briareus.radiograph — Method
radiograph(rg::Radiograph, target, deposition; object = (),
           model = kshell_ce_model()) -> NamedTuple

The radiograph that rg records of target, with its backlighter foil driven by deposition, the laser power on each element in TW, as backlighter_signal takes it.

object lists the parts that attenuate, as part => material (with the density of the material) or part => (material, density) (g/cm³), with materials as in mass_attenuation. Each part is a closed surface filled with its material, and along each ray the transmission is exp(−Σ μ/ρ · ρ · L), with L the length of the ray inside each part. Where parts overlap their attenuations add, so a hollow shell is its outer surface with the material of the shell and its inner surface with the negative density. The parts of the object do not obstruct, and every other surface part except the foil does, as hardware does in backlighter_signal.

Returns (; images, open, transmission, weights, times, magnification, line, ce, sigma, extrapolated):

  • images: one matrix per frame (one for :integrated) of detected photons per mm² of detector at each object-plane point (row 1 at the top, up). Per detector pixel, the values are multiplied by its area.
  • open: the same over the whole emission without the object (the open field).
  • transmission: the image of the whole emission over open (NaN where open is 0), which is the transmission of the object as the radiograph measures it, blurred.
  • weights: the fraction of the emission that each frame records (1 for :integrated), so images[k] = weights[k] × transmission × open; times: the times of the frames.
  • magnification, line (keV), and from the source ce (the He-α energy over the laser energy), sigma (1σ of ln CE, by which every image is uncertain) and extrapolated.
