Diagnostic definitions

A synthetic diagnostic is described by a definition file: one TOML file per instrument, holding its line of sight, its hardware and its recording, each value with its source. The public definitions ship with the package (data/diagnostics); a user group keeps its own, including details that are not public, in directories on a search path, and modifies a public definition by extending it rather than copying it. diagnostic builds the instrument of a definition (for the soft x-ray power kind, a DanteView for dante); check_diagnostics reports every problem in the files on the search path, by file and key.

The search path

diagnostic_paths lists the directories read, in order of precedence: the built-in definitions, the directories saved in the user configuration file (diagnostic_config_path, key diagnostics.paths), those of the environment variable BRIAREUS_DIAGNOSTICS (for batch jobs; ;-separated on Windows, :-separated elsewhere) and those added for the current session. Directories are read recursively. A definition later on the path shadows an earlier one with the same id, with a warning naming both files. A directory is added once and kept for later sessions with

add_diagnostic_path("//groupserver/briareus/diagnostics")

and remove_diagnostic_path removes it. The built-in constructors (dante1, dante1_responses) read the built-in definitions only, so user files do not change them; diagnostic("nif_dante1") takes the search path.

A definition file

Every file has a header: schema (the format version, DIAGNOSTIC_SCHEMA), id, and either kind or extends; optionally name, facility, public (false for non-public detail), valid_from and valid_to (dates), shots, and the provenance keys source, confidence (H, M or L, as in the research notes) and note, which every table may also carry. Keys are checked: an unknown key or a value of the wrong type is an error naming the file and the key. Units are in the key names (theta_deg, energy_eV, thickness_um, solid_angle_sr).

The kind xray_power (Dante, Sentinel) takes:

TableKeys
[line_of_sight] (required)theta_deg, phi_deg: the instrument's direction from TCC
[view]field_of_view_mm (the collimated field, a disk of this diameter normal to the line of sight; without it the view looks through through alone), center_part or center_mm (the field's center, a part's centroid or a point; default TCC), through (the aperture looked through, and the reference for Tr; default leh_bottom without a field of view, none with one), pixels (rays per side; default 400), area_mm2 (the area Tr is quoted over; default the aperture's initial area), area_part (Tr over that part's visible projected area), area_open = true (Tr over the hole's open area at each time, from the model's entrance-hole closure) or area_history_csv (a measured area history: time in ns, area in mm²)
[recording]mode = "history"
[[channel]] (one per channel)number and solid_angle_sr (required); energy_eV (nominal band energy; default the response's peak); filters (an array of { material, thickness_um }, optionally density_g_cm3, or { transmission_csv }); grid (open fraction; default 1); mirror ({ kind = "SiO2", angle_deg }, calibrated; { kind = "mlm", angle_deg = 1.9 }; { kind = "fresnel", material, angle_deg }, optionally roughness_nm and density_g_cm3, an uncalibrated GrazingMirror for C, Be, B₄C and other coatings; or { reflectivity_csv }); cathode ("Al", "Cr" or "Ni", xrd_sensitivity) or sensitivity_csv; or a measured response_csv in place of all of these
top levelremove_channels (numbers dropped from the definition extended)

The kind xray_imager (the SXI, G-LEH and gated imagers) builds an XrayImager and takes:

TableKeys
[line_of_sight] (required)theta_deg, phi_deg
[optic] (required)kind = "pinhole", diameter_um, distance_mm (the pinhole from the object), magnification; energy_eV (the photon energy of the diffraction blur)
top levelfilters (required; as a channel's, an empty array for none), mirror (as a channel's)
[detector] (required)absorber and absorber_um (the absorbing layer, e.g. Si 15 µm) or efficiency_csv; kind, pixel_um, pixels (across, down)
[view]width_mm (the object-plane field; default the detector's extent over the magnification), pixels (samples per side; default 256), center_part or center_mm, up (the image's up, a chamber direction)
[recording]mode = "integrated" (default) or "gated" with times_ns, gate_ns (FWHM) and gate_shape ("gaussian" or "square")

detected_radiance weighs each element's radiance by the imager's response over its spectrum, imager_image renders it on the object plane and blurs it by the pinhole, and imager_record integrates the images of a history over the recording's gates.

A field of view takes in every surface of the target facing the instrument, occluded by any part: a NIF Dante's is ±30 mm at TCC (the 2004 design), wider than any hohlraum, so windows, packages and shields enter the signal as they would on the shot. Within an extended definition, giving one of area_mm2 / area_part or center_part / center_mm drops the other inherited from the base.

The response of a channel is the product of its parts (DanteResponse). Measured curves are CSV files with a header line and two columns, photon energy (eV) and value (a fraction, or V/GW for a sensitivity or a response), at a path relative to the definition file (TabulatedCurve); outside a table a factor holds its end values and a whole response is zero, and check_diagnostics warns when a table does not cover 50 eV – 20 keV.

A user group completes one by extending it with the values it holds, e.g. Omega's solid angles, one [[channel]] table per channel with number and solid_angle_sr.

Extending a definition

A file with extends = "<id>" takes that definition and replaces what it gives: tables key by key, channels by number (a channel's listed keys replace the base channel's; a new number adds a channel), and remove_channels drops channels. A campaign that replaced Dante 1's channel 6 filter, removed channel 16 and added a calibrated channel is, in full:

schema = 1
id = "group_dante1_campaign"
extends = "nif_dante1"
name = "Dante 1, campaign configuration"
public = false
remove_channels = [16]

[[channel]]
number = 6
filters = [{ material = "Cu", thickness_um = 1.1 }]
source = "campaign shot sheet"

[[channel]]
number = 19
energy_eV = 1000
solid_angle_sr = 6.5e-7
response_csv = "calibrations/ch19.csv"

DiagnosticDefinition.chain lists the files a definition was resolved from, and public is false when any of them sets public = false. Values a definition lacks to be built (Dante 2's channels are not public, for example) are reported as :missing by check_diagnostics, with the key to supply.

Definitions in sessions

A saved GUI session holds the definitions of the diagnostics it records, so that it records the same instruments on any computer. diagnostic_table writes a resolved definition as one standalone table (no extends; each CSV path mapped, e.g. to a copy stored beside it), diagnostic_definition reads such a table back, checked as a file on the search path is, and diagnostic_diff lists the keys in which two definitions differ, CSV files compared by content: on opening a session, a saved definition that differs from the search path's of the same id is reported with those keys, and the saved one is used unless the search path's is chosen.

New kinds

register_diagnostic_kind adds a kind: a schema of DiagnosticFields and a builder. The format already reserves the recording modes of the kinds planned next (time-integrated, gated and streaked imagers, radiography, streaked optical diagnostics); see reference/diagnostics-design.md in the repository.

Briareus.DiagnosticDefinition — Type
DiagnosticDefinition

A diagnostic definition read from a file and resolved through extends: id, name, kind, file (the file that defines it), chain (the files it was resolved from, the base first), public (false when any file in the chain sets public = false) and data (the resolved table, CSV paths made absolute). diagnostic builds the instrument.

Briareus.DiagnosticField — Type
DiagnosticField(type; required = false, doc = "")

One key of a diagnostic kind's schema (register_diagnostic_kind): type is Real, Integer, String, Bool, :date, Vector{String}, Vector{Real}, a schema table (a Dict{String,DiagnosticField}) or a one-element vector holding a schema table (an array of tables). Keys ending in _csv name a CSV file, a path relative to the definition file.

Briareus.DiagnosticIssue — Type
DiagnosticIssue

A problem found in a definition file (check_diagnostics): file, key (the path to the value, e.g. channel[6].filters[1].thickness_um), message, and level: :error (the file cannot be used), :missing (a value the definition lacks to be built, e.g. one that is not public) or :warning.

Briareus.add_diagnostic_path — Method
add_diagnostic_path(dir; save = true) -> Vector{String}

Add the directory dir to the diagnostic search path, after those already on it: save = true stores it in the configuration file (diagnostic_config_path), so later sessions find it; save = false adds it for this Julia session only. Returns the search path (diagnostic_paths).

source
Briareus.check_diagnostics — Method
check_diagnostics(; paths = diagnostic_paths()) -> Vector{DiagnosticIssue}

Read every definition on paths, resolve extends, check each against its kind's schema and build it, and return the problems found (DiagnosticIssue): errors (unknown keys, wrong types, unreadable CSV files, unknown materials), values a definition lacks to be built (:missing) and warnings (shadowed ids, CSV tables that do not cover a channel's energy range). An empty result means every definition builds.

Briareus.diagnostic — Method
diagnostic(id; paths = diagnostic_paths(), kwargs...)
diagnostic(def::DiagnosticDefinition; kwargs...)

Build the instrument of definition id found on paths (diagnostics), or of def: for kind = "xray_power" a DanteView. kwargs go to the kind's builder (for xray_power, those of DanteView, e.g. pixels), replacing the definition's values. A definition that lacks a value the instrument needs (e.g. a channel set that is not public) throws, naming the key to supply.

Briareus.diagnostic_paths — Method
diagnostic_paths(; builtin = true) -> Vector{String}

The diagnostic search path, in order of precedence (a later definition of an id shadows an earlier one): the built-in definitions (data/diagnostics, unless builtin = false), the directories saved in the configuration file (diagnostic_config_path), those of the environment variable BRIAREUS_DIAGNOSTICS (separated by ; on Windows, : elsewhere), and those added for this Julia session (add_diagnostic_path with save = false).

Briareus.XrayImager — Type
XrayImager(theta, phi; pinhole, distance, magnification, width, pixels = 256,
           center = 0, up = ẑ, filters = (), tables = (), mirror = nothing,
           detector = nothing, detector_pixel = 0.0, energy = nothing,
           mode = :integrated, times = Float64[], gate = 0.0, gate_shape = :gaussian)

A pinhole x-ray imager on the line of sight (θ, φ) (degrees, from target chamber center toward the instrument): a pinhole of diameter pinhole (mm) at distance (mm) from the object, imaging at magnification onto a detector of pixel detector_pixel (mm). The object plane is sampled over a width × width mm field about center (a point, or a part's name) on pixels × pixels rays; up (a chamber direction) is the image's up.

The spectral response R(E) is the product of the filters (filter_transmission materials with thicknesses in mm, as DanteResponse's, and measured tables), an optional mirror (as DanteResponse's) and the detector's absorption: detector = (:Si, 0.015) absorbs 1 − e^{−μρt} of the photons in 15 µm of Si (no dead layer), a TabulatedCurve is a measured efficiency, and nothing absorbs every photon. R is a fraction, so images are of detected x-ray energy.

The point-spread function on the object plane is the pinhole's geometric penumbra, a uniform disk of diameter penumbra = d(1 + 1/M), convolved with a Gaussian of the summed variances of its Fraunhofer diffraction (FWHM diffraction = 1.03 λ distance / d at photon energy, eV) and of the detector pixel (a box of detector_pixel / M). The Gaussian is an engineering approximation: the Airy pattern and the box are not Gaussian, and a pinhole whose Fresnel number d² / λz is near 1 is not in the far field. energy defaults to the mean photon energy of what the imager detects of a 300 eV Planckian (an engineering default); a definition states it.

mode is :integrated (one image of the time integral) or :gated (one frame per time of times, ns, each the integral of the image against a gate of FWHM gate ns, :gaussian or :square, of peak 1).

Briareus.detected_radiance — Method
detected_radiance(im::XrayImager, B::AbstractVector) -> Vector{Float64}
detected_radiance(im::XrayImager, sol::RadiationSolution) -> Vector{Float64}
detected_radiance(im::XrayImager, s::SpectralSolution) -> Vector{Float64}

The radiance of each element that the imager detects (TW mm⁻² sr⁻¹ of detected x-ray energy): B ⟨R⟩ / π, the element's Lambertian radiance times the imager's response averaged over its spectrum. For a gray radiosity B (TW/mm²) the spectrum is the Planckian at the element's brightness temperature (B/σ)^{1/4} (an assumption: the reflected part of the radiosity carries the incident spectrum); for a SpectralSolution, each group's radiosity with the Planckian of the element's wall temperature within the group.

Briareus.imager_image — Method
imager_image(im::XrayImager, t::Target, L::AbstractVector) -> Matrix{Float64}
imager_image(im::XrayImager, sol) -> Matrix{Float64}

The image on the object plane (row 1 at the top, up) of the per-element detected radiance L (detected_radiance), blurred by the imager's resolution: TW mm⁻² sr⁻¹ of detected x-ray energy. For a solution, its target and detected_radiance(im, sol).

Briareus.imager_record — Method
imager_record(im::XrayImager, t::Target, time, L::AbstractMatrix) -> NamedTuple

What the imager records of a history: L the detected radiance per element (rows) at each time of time (ns, columns; detected_radiance of each step), taken as linear between the times. (; images, times): for mode = :integrated one image, the time integral (kJ mm⁻² sr⁻¹, as TW·ns), times empty; for :gated one frame per gate time, the integral against the gate (peak 1; kJ mm⁻² sr⁻¹), times the gate times.
