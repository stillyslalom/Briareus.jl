Input and output

Beam tables in a canonical CSV (write_beam_table, read_beam_table), with column and unit mapping for foreign tables; STL (read_stl, read_stl_solids, write_stl); and write_results, which exports per-element laser, radiosity and flux, per-component and per-beam power, and the Legendre and $Y_{lm}$ modes of the capsule as CSV for postprocessing. VisRad files are on VisRad interchange.

Briareus.BEAM_COLUMNS — Constant

Column names of the canonical beam table (see write_beam_table).

Briareus.read_beam_table — Method
read_beam_table(path; columns = Dict(), scale = Dict(), defaults = (;), template = nothing)
    -> Vector{Beam}

Read beams from a CSV. Canonical column names (see write_beam_table) are recognized case-insensitively. For foreign tables, columns maps a canonical field to the column name in the file, e.g. Dict(:aim_x => "X (cm)", :theta => "Theta"), and scale multiplies a field after reading, e.g. Dict(:aim_x => 10, :aim_y => 10, :aim_z => 10) for cm → mm. Fields missing from the file come from defaults (a NamedTuple of canonical fields). When template is a beam vector, they come instead from the template beam with the same name, so that a pointing table can update a facility beam set. Otherwise they take the Beam defaults. A field that is not a number throws an ArgumentError that names the line and column of the file.

Briareus.read_csv — Method
read_csv(path; comment = '#') -> (header::Vector{String}, rows::Vector{Vector{String}})

CSV reader without dependencies (RFC 4180 quoting). A field in double quotes may contain the delimiter, line breaks and the comment character, with "" for a quote. Its text is kept as quoted, while unquoted fields are stripped of surrounding blanks. Lines that are blank or start with comment (after blanks, outside a quoted field) are skipped. Tab- or semicolon-separated files are detected from the header line. A row with fewer fields than the header, a row with more (other than empty trailing fields), and a quoted field left open at the end of the file throw an ArgumentError with the line number.

Briareus.read_stl — Method
read_stl(path; scale = 1.0) -> Mesh

Triangle mesh from an STL file (binary or ASCII), one patch per facet, with vertex coordinates multiplied by scale. STL files do not specify units, so scale is 1 for millimeters, 10 for centimeters and 25.4 for inches. Facet normals in the file are ignored, and the winding determines the front side, as STL specifies (counterclockwise seen from outside). Exported CAD often mixes windings, so the mesh should be passed through orient_mesh, and through coarsen_mesh before view factors.

All facets of the file go into one mesh, also when an ASCII file contains several solid … endsolid blocks, one per CAD body, as many exporters write them. read_stl_solids keeps them apart. A binary file is recognized by its size, 84 + 50n bytes for the n facets that its header announces. Binary files whose header begins with "solid", as SolidWorks writes them, are therefore read as binary. ASCII keywords are read in any case, with any whitespace and line endings.

source
Briareus.read_stl_solids — Method
read_stl_solids(path; scale = 1.0) -> Vector{Pair{String,Mesh}}

The solids of an STL file as name => mesh pairs in file order, each mesh as read_stl reads it (one patch per facet, coordinates multiplied by scale). An ASCII file gives one pair per solid <name> … endsolid block, named by the rest of its solid line. The k-th solid is named "solid<k>" when that line is blank, and repeated names are kept as they are. An empty solid gives an empty mesh. A binary file does not have solids, and it gives one pair named after the file. A target is built from the parts with, for example, Target([Component(n, orient_mesh(m), gold()) for (n, m) in read_stl_solids(path)]).

Briareus.write_beam_table — Method
write_beam_table(path, beams) -> path

Write beams as CSV with the canonical columns name, quad, group, theta, phi, power, aim_x, aim_y, aim_z, defocus, spot_a, spot_b, spot_order, spot_angle, spot_halo, spot_halo_scale, spot_halo_order, fnumber, wavelength, dlambda (mm, TW, degrees, µm, Å). The hohlraum-cylindrical aim coordinates aim_r (toward the port azimuth) and aim_phi_offset (tangential) are appended for reference.

Briareus.write_element_table — Method
write_element_table(path, target, fields...; elems = all) -> path

Per-element CSV: index, component, side, centroid (mm), normal, area (mm²), polar and azimuthal angle of the centroid (degrees, about TCC), then one column per name => values pair in fields (e.g. :H => sol.H, :laser => laser_flux(dep, t)). On a target with parts split for computation (curved_components), a part column follows component.

Briareus.write_results — Method
write_results(dir, target, dep; sol = nothing, beams = nothing, observe = nothing,
              lmax = 8) -> Vector{String}

Write the results of a calculation to the folder dir as CSV files, for postprocessing or comparison with another code, and return their paths:

  • elements.csv — per element (write_element_table): absorbed laser power (TW) and intensity (W/cm²), and with a radiosity solution sol the x-ray source, radiosity and incident flux (W/cm²), albedo and transmitted fraction;
  • components.csv — per part: absorbed laser power (TW, front and the unmodeled back side), and with sol the x-ray power absorbed, escaped (apertures) and transmitted (thin foils, gaps) from energy_balance. A part is a component unless it was split for computation by curved_components, in which case its pieces are summed;
  • beams.csv — with beams (in the order of the deposition): the name, port angles, and delivered and landed power (TW) of each beam;
  • legendre.csv and ylm.csv — with observe (part or component names) and sol: the Legendre moments aₗ (write_moments) and the real spherical-harmonic coefficients c_lm of the observed incident flux, with their ratios to the mean term;
  • summary.txt — totals (delivered, landed, missed; x-ray source, lost).

Briareus.write_stl — Method
write_stl(path, x; binary = true, scale = 1.0, apertures = true, name = "briareus") -> path

Write x as an STL file for CAD or another code. x is a Mesh, a Component, a Target, or a vector of components or of name => mesh pairs. Every triangle becomes a facet whose normal is computed from its winding, toward the front side. Vertex coordinates are divided by scale, since STL files do not specify units: 1 writes millimeters, 10 centimeters and 25.4 inches. read_stl(path; scale) then reads the same geometry back.

binary = true writes binary STL with Float32 coordinates, so a coordinate of size L moves by up to about 6e-8 L. Binary STL has no solid names, so the header lists them. binary = false writes ASCII STL with one solid <name> … endsolid <name> block per component (or pair), in order, at full Float64 precision. read_stl_solids reads them back as named parts, and whitespace in a name is written as _. A single mesh is named name.

A two-sided component is written once, wound toward its front side. Apertures, which are laser entrance holes and other open windows transparent to light, are written as separate solids so that a CAD user sees them. apertures = false leaves them out, e.g. for a code that would take every facet for a wall. A closing lip (aperture(...; closure), hohlraum(; leh_closure)) is a plasma model and is not a part. A lip named <hole>_lip is written in the solid of its aperture <hole>, so the entrance hole comes out whole, at its full radius. A lip without its hole is written as a separate solid. The exact CurvedSurface of a component is not written, only its facets, and the patch structure is lost, since read_stl returns one patch per triangle.
